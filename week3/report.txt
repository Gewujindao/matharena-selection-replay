十、局限
1. 有限账本描述：范围只是这四场比赛中有完整记录的相邻档位配置，实际只涉及 OpenAI 的 o3-mini 与 o4-mini 两个基础端点、9 个有效 cell；不推广到所有数学题、所有 LLM 或所有 reasoning 档位。CMIMC 缺失，汇总是三场比赛的描述。
2. cell 不是独立样本：同一基础端点的两个 cell 共用中间档（medium）的记录，同题、同配置和四槽也共享记录；不做显著性筛选，不给独立 pair 区间或把逐行 bootstrap 当复现。
3. 档位比较是同一基础端点不同 reasoning 档位的缓存比较，包含预算和调用条件差（例如 o4-mini high 有输出 token 恰为 64000 的记录），不识别纯能力效应；命名相同不证明权重或服务历史恒定。历史请求参数、重试/替换链、真实随机种子、判分版本与 usage 归属均为 UNKNOWN，可交换性与独立性 UNKNOWN；账本恒等式不需要这些假设，把槽均值解释为 iid 成功概率则需要。
4. 判分层是各 revision 存储的 correct，没有重判、没有另写宽松解析；原 parser 版本 UNKNOWN。
5. 已见材料：HMMT o3-mini medium→high 是第二周开发材料，已单列并另给去掉它的汇总；HMMT o3-mini low→medium 的 B 侧（medium 档）记录也在第二周解码过，但按冻结规则（比赛×pair）不算已见 cell。第二周及更早的工作看过这些配置的公开榜分，配对范围本身不是未见验证。
6. 覆盖受冻结规则限制：严格读取 “--<档位>” 后缀使 GPT-5.2 high→xhigh（AIME、HMMT）未进入普查；八槽提示须逐字节相同使 3 个 cell 成为 NA。这些是覆盖缺口，不是模型机制被否定。
7. 30%–70% 分层只是预定描述层，非效果保证；K 小（最小 4）的 cell 中单题就能明显改变 R、D、C。

十三、执行中自行决定的操作细节（均在解码 correct 之前写进代码与 frame.json）
- 档位阶梯 minimal < low < medium < high < xhigh；显示名末尾括号内容恰为阶梯词（不分大小写）才算档位标签，其他末尾括号（Think、05-06、preview 等）不算，留在基础名里
- 路径后缀只认最后一段路径里最后一个 "--" 之后、恰为阶梯词的部分；单个连字符（-low、-high）不是冻结的 --<档位> 后缀；路径只去掉固定前缀 configs/models/ 与后缀 .yaml
- 档位优先取显示名标签，没有时取路径后缀；两处都有但不一致 → 该配置 NA；一个配置值带不止一个 model_name → 该配置 NA
- 基础端点 = (显示名去掉末尾档位括号及其前空白, 路径去掉 --<档位> 后缀)，两者都相同才算同一端点；同端点同档位多于一个配置 → 该端点本赛 NA
- 合格 pair：同一端点、阶梯上相邻的两档，A 为较低档；不相邻不接
- 题框 = 该比赛冻结副本全部行中出现的不同 problem_idx（source 列全为空，不参与键）
- 每个 cell 每题：A、B 各 idx 0..3 恰一条（除 correct 外各列完全相同的重复行折叠，第二阶段再核 correct 是否也相同）；内容不同的重复或 0..3 以外的 idx 即违约；缺任何一条即违约
- 题文/gold：每题 8 条保留记录的 problem 与 gold_answer 各只有一个取值，gold 非空
- 完整提示 = (user_message, all_messages 中所有非 assistant 条目按原顺序、键排序的规范 JSON)；须 user_message 非空、all_messages 为含 user 轮的 JSON 列表；八槽须逐字节相同
- 已存 correct 非缺失：只读 parquet 定义层（空值掩码），不解码取值；物理类型须为 BOOLEAN
- 响应状态（沿用第二周）：answer 非空即保留（token 为 0 也保留，usage 按原记账层级读）；answer 空且 output_tokens>0 为已保存截断，按原 correct 计；answer 空且 output_tokens 空/0 为未知响应状态 → 违约
- 任一题违约 → 该 cell NA，不取两边交集、不删题、不换配置；NA cell 留在覆盖分母
- 主槽固定 idx0 筛选、idx1–3 复评；四槽循环只作敏感性
- 已见 cell：第二周 HMMT openai/o3-mini--medium → openai/o3-mini；第一周 AIME claude-35 → claude-37 不是档位 pair，不会出现在合格 cell 中
- 预定描述分层（第二部分“30–70%只作预定描述分层”）：A（较低档）在全题框四槽合计的缓存正确率落在闭区间 [30%, 70%]；只作描述，不用于入选
- 合同里的 correct 非缺失只读 parquet 定义层（空值掩码），取值字节在第一阶段从未解码。
- 汇总中某个量在某 cell 无定义（K = 0）时，该 cell 在该量的这一层计为无定义；本次所有有效 cell 的 K ≥ 4，未出现 K = 0。
- 冻结第一部分第 7 条要求的独立重算照做。
- 写 frame 之前跑过两个只读探查（w3_probe_schema.py：列结构与配置名；w3_probe_prompts.py：按规则得到的合格配置的消息角色结构），都不读 correct；完整提示的定义在探查之前已写进代码，探查只确认 all_messages 的结构是 [user, assistant]。
