MathArena AIME 2025 按答错筛题回放——结果报告

证据等级：前瞻（分析计划冻结后才首次取数和计算）。所用数据是公开缓存的回顾性记录，不是未见公开榜分的前瞻实验；这是冻结记录回放，不升级为模型随机化总体推断。

一、各道门
- 入场门（数据绑定）：通过。HF 数据集 MathArena/aime_2025_outputs，固定 revision 16e93d3bb9b0a25ea9422893464d46b3c5ff0ae9（该 commit 日期 2026-09-11，取数时仍是 main 的最新 commit），单个 parquet data/train-00000-of-00001.parquet，142685920 字节；本地字节 SHA256 与登记的 LFS oid 一致；许可 CC-BY-NC-SA-4.0。
- 成本门：通过。草稿没有写成本门的数值阈值；按原文保留原生生成上限、不补 retry、不重查询，因此新增 API 调用为 0。downloads/ 共 137.0 MiB（上限 1 GB），单进程、1 线程、BelowNormal、进程内存上限 2 GiB（job object），每次重活前可用内存都 ≥ 1500 MB。
- 执行门：通过。两锁定配置在该 revision 中的路径值原样出现：A = ['anthropic/claude-35']（['Claude-3.5-Sonnet']），B = ['anthropic/claude-37']（['Claude-3.7-Sonnet (Think)']），无需去前后缀，未做模糊匹配。候选题 30 道；A、B 两边 idx=0..3 唯一齐全、题文 hash 与 gold 一致的完整框 F = 30 道；排除 0 道。
- 种子：按草稿命名空间规则 SHA256("line160/v1|HFrevision|source|problem_idx|idx") 展开 120 条，互不相同，题内并列 0 处（并列按 idx 升序）；与上级目录中已登记的种子无碰撞（扫描 20173 个文本文件中的 10–20 位整数字面量、64 位十六进制字面量和命名空间串，另核 85 个登记区间）。这些哈希只给现有记录分派角色，不是原调用的随机种子。

二、主结果（预注册主量：p0 筛选，p1–p3 复评）
- 完整框 F = 30 道题中，旧配置 A（Claude-3.5-Sonnet）在 p0 槽答错的题 S 共 K = 28 道。
- 在这 28 道所筛题上：A₁（未参与筛选的旧配置角色，p1–p3 三条记录正确率均值）= 1/84（0.0119）；B₁（新配置 B，同三槽）= 10/21（0.4762）。
- G_naive = mean(B₁ − A₀) = 10/21（+47.6 个百分点）。
- R = mean(A₁ − A₀) = 1/84（+1.2 个百分点）。R 是筛错后再评分的缓存记录回升。
- D = mean(B₁ − A₁) = 13/28（+46.4 个百分点）；恒等式 G_naive − R = D 精确成立。
- 读法：在按 A 答错筛出的题上，B 相对 A 的表面提升 G_naive 中，有 R 这一部分是 A 自己在未参与筛选的三条记录上就有的回升；扣掉后剩 D。B 与 A 的差只称记录配置差（B：max_tokens 64000、thinking 32000、温度 1；A：max_tokens 8000，官网未列温度），不称等预算纯代际提升。
- 结论：A 在本缓存中几乎总答错（F 上 120 条记录只对 4 条），所以按 A 答错筛题几乎不改变人群（K = 28/30）。筛错后的缓存记录回升 R 只有 1.2 个百分点，G_naive（47.6 个百分点）与 D（46.4 个百分点）几乎相同；D 与全框 D_F（45.6 个百分点）只差 0.9 个百分点。四套轮换下 R 在 1.2 到 4.4 个百分点之间，D − D_F 在 -1.8 到 +0.9 个百分点之间。就这批冻结记录而言，按答错筛题造成的差异很小。但这是 A 几乎全错的地板情形（A 的总正确率 3.33% 在冻结前已公开），R 和 D − D_F 小主要由此决定，不能外推到旧配置正确率较高时的错筛。

三、次要量
- D_F = 完整缓存框 F 内 mean(B₁ − A₁) = 41/90（+45.6 个百分点）；D − D_F = 11/1260（+0.9 个百分点）。
  F 齐全 30 题，D − D_F 量化本缓存的错筛组成差。已知有限框直接比较，无需 IPW；这不是模型随机化总体或其他题库的回校。
- 角色协议敏感性（p0 轮换到四个位置，其余三条复评；四套共享同一缓存，不是四次独立实验，不除以 √4）：
    p0 筛选：K = 28，G_naive = 10/21（0.4762），R = 1/84（0.0119），D = 13/28（0.4643），D_F = 41/90（0.4556），D − D_F = 11/1260（0.0087）
    p1 筛选：K = 29，G_naive = 14/29（0.4828），R = 1/29（0.0345），D = 13/29（0.4483），D_F = 7/15（0.4667），D − D_F = -8/435（-0.0184）
    p2 筛选：K = 29，G_naive = 41/87（0.4713），R = 2/87（0.0230），D = 13/29（0.4483），D_F = 41/90（0.4556），D − D_F = -19/2610（-0.0073）
    p3 筛选：K = 30，G_naive = 1/2（0.5000），R = 2/45（0.0444），D = 41/90（0.4556），D_F = 41/90（0.4556），D − D_F = 0/1（0.0000）
  四套中有定义的 4 套：D 在 0.4483 到 0.4643 之间，R 在 0.0119 到 0.0444 之间，D − D_F 在 -0.0184 到 0.0087 之间。
- 不确定性：按预注册不强加 95% CI。主结果是有限记录的精确描述；上面的轮换范围只反映角色分派协议的敏感性。模型随机化 CI 须先证明原重复机制；抽题 CI 须另定题目总体和题族抽样假设，逐回答 bootstrap 不能替代，I/II 两份试卷也不能当作充分独立的簇。
- 描述性背景（非预注册量，只帮助读 D_F）：F 上四个槽合计，A 正确率 0.0333，B 正确率 0.4917。

四、局限（草稿列出的全部，另加本次执行中出现的）
1. 这是公开缓存的回顾性分析，不是未见公开榜分的前瞻实验；候选配置在读官方模型页时已固定，未按效果另挑模型，也不换模型追求显著结果。
2. A 的官网页面未列温度，这不等于温度零；没有补写默认值。
3. A、B 的预算和推理模式不同（B 有 32000 thinking、64000 上限、温度 1；A 上限 8000），只能称记录配置差，不能称等预算的纯代际提升。
4. 没有核到历史配置文件 hash、调用时间、resolved 模型回执、原 seed/retry 和 parser 提交（manifest 中均记 UNKNOWN）。GitHub 上两个配置文件有多次提交（manifest 记有 commit 列表，最晚 2025-12-22），而逐条生成时间未知，所以当前 main 版本不一定是生成时版本。日期端点只是可核代理，不是已审计的权重 hash；这些只是缓存身份线索，也未证明旧端点现在仍可调用。因此只做冻结记录回放，禁止升级为模型随机化总体推断。
5. 不以竞赛年份保证未污染。
6. idx_answer 是 attempt 索引，不是 seed 或独立保证；命名空间哈希只分派现有记录角色，不制造原调用随机种子。
7. 每槽的首次请求和替换链、原收集端的重试/成功替换都不明（记 UNKNOWN）；缺请求链不会靠删行变成独立。数据里没有逐条生成时间，只知道快照收录时间（revision commit 日期 2026-09-11），没有编造生成日期。
8. R 只是筛错后再评分的缓存记录回升；只有在调用条件相同、重复可交换且筛选与复评的随机性独立都得到支持时，才能解释为 fresh 重测回升，本次均未核实。若旧榜分本来就来自独立评估，就不该再扣 R。
9. D 不恢复来源总体，也不识别训练机制、家族惩罚或真实 HLE 筛选史。
10. D_F 与 D − D_F 只及本缓存框（F 齐全 30 题），不是模型随机化总体或其他题库的回校。
11. 主判分层是该 revision 存储的 correct / parsed_answer，没有自行做字符串等值；原 parser 版本 UNKNOWN，不能排除解析漂移。以后若统一重判，须先另锁共同 parser/gold 版本和冲突规则并保留原层，不能看了 D 再选解析器。
12. 已保存的截断和拒答一律按锁定的 correct 计，没有补 retry 或重查询；生成上限保留原生值，没有按实际 token 裁样。（A 有 0 条、B 有 0 条 output_tokens 超过官网上限；可见答案为空但有输出 token 的已保存截断：A 0 条、B 0 条。）
13. 30 题固定，结果不带 95% CI；四套轮换共享同一缓存，不能当四次独立实验或除以 √4。
14. 执行顺序说明：草稿末句写“首周只核元数据门、冻结 manifest/角色和判分层，不运行回放或指标”。冻结补充节（以其为准）要求报告前瞻结果，所以照做；但仍保持草稿的先后顺序——manifest、排除表、角色表和种子核对先封存为只读，之后才解封 correct 列。（第一阶段为核对“判分字段缺失”曾解码 correct 列，但只保留是否为空的标志和行摘要，取值未输出、未用于任何计算。）
15. 实现说明：指定环境没有 pyarrow，按要求未安装任何包；改用自写的纯 Python parquet 读取器（Snappy、RLE、字典编码）。单元测试通过，且数值列解码经 cost = 输入 token × 单价 + 输出 token × 单价 的恒等式核对，7915/7915 行成立。
16. 增补诊断发现的记录差异：A 在 AIME I 上用了不同的提示词（“modulo 1000” 版），这属于 A/B “记录配置差”的一部分；A 在 AIME I 上把四次调用的 token/费用合计记在 idx 0、idx 1–3 记为 0，说明 A 的 AIME I 记录出自与 AIME II 不同的收集/记账版本（题间异质）。（复核更正：这不是题内四槽“并非同一收集路径”的证据，也不直接削弱题内可交换性；但“重复可交换、筛选与复评随机性独立”仍未核实，R 仍只能按缓存记录回升读。）

附：增补诊断（非预注册，不改变任何冻结规则或数值）
- 读取器核对：F 上四槽合计正确率 A = 3.33%、B = 49.17%，与 MathArena 官网模型页所列 AIME 2025 正确率（3.33%、49.17%）一致，说明 correct 列的合计解码无误（逐槽取值另经复核者独立读取器核对，240/240 一致）；也提示官网榜分就来自这批缓存记录，并非独立评估，所以 R 不能因“旧榜分已独立”而免扣。
- 以下三项在封存之后、解封 correct 之前查看（只看提示词、token 计数和答案文本是否重复，答案文本只以 SHA256 比较）：
    1）A 与 B 的提示词在第 1–15 题（AIME I）不同：A 为 “Output the final answer modulo 1000”，B 为 “The answer is an integer between 0 and 999 inclusive”；第 16–30 题相同。题文 hash 和 gold 一致，所以按冻结规则仍配对，未排除。
    2）A 在第 1–15 题的 idx 1–3 记录的输入、输出 token 均为 0（答案非空）；B 全部有计数。（复核更正）idx 0 上的计数不是单条计数，而是同题四次调用的合计：这 15 题 A 的 idx 0 input_tokens 都恰为单次提示的 4 倍（B 的单次 input_tokens 减去 A 的 1/4，14 题为常数 33、1 题为 37），output_tokens 也与四条答案的合计长度相符。类似的 token 记为 0 的模式还见于该 revision 中另外 12 个早期配置的 AIME I 记录（多数为 idx 1–3）。所以这是记账方式（合计记在 idx 0），不能说明 idx 0 与 idx 1–3 来自不同收集路径；它只说明 A 的 AIME I 记录与其 AIME II 记录、与 B 的记录出自不同的收集/记账版本。
    3）A、B 在任何一题内四条答案文本都互不相同（A 有重复的题 0 道，B 0 道）。
- 该 revision 中 source 字段在所有行都是字符串 “None”；命名空间哈希按数据原值使用 “None”，配对实际靠 problem_idx 与题文 hash。

五、预先确定的操作定义（在使用 correct 取值之前写进代码并封存）
- 候选题 = 该 revision 全部行中出现的不同 (source, problem_idx)
- idx=0..3 各恰一条（完全相同的重复行折叠）；同键内容不同或出现 0..3 之外的 idx 视为冲突，整题两边排除
- 明确技术失败/无有效响应 = answer 为空或仅空白 且 output_tokens 为空或 0；answer 为空但 output_tokens>0 视为已保存截断，保留并按锁定 correct
- 判分字段缺失 = correct 为空；parsed_answer 为空但 correct 非空视为已判分
- 配对：每题所有保留 A/B 行的题文 SHA256 与 gold_answer 各只有一个值
- 主量为轮换 0（p0 筛选），轮换 1..3 只作角色协议敏感性
