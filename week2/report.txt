六、局限（冻结设计列出的，另加本次执行中出现的）
1. 公开缓存的回顾性分析；配对按冻结前可见的公开榜分选型，配对选择不算未见效果验证。
2. 这是同一基础模型不同 reasoning 档位的缓存比较，包含预算/调用条件差（B 有 17 条输出超过 32000 token），不识别跨代或纯能力效应；A 只称较低档旧配置，不称旧一代模型。
3. 当前 API/batch 一致不证明历史调用一致，更不证明 iid。调用时间、resolved endpoint、完整提示之外的请求参数、尝试/重试与替换链、真实随机种子、判分版本和 usage 归属都不明（UNKNOWN），可交换性与独立性仍 UNKNOWN。账本恒等式无需这些假设；把槽均值解释为 iid 的题目成功概率则需要。
4. 30–70% 不保证偏差大：仅在条件 iid 总体模型下，μ = E p_A < 1 时 R_pop = μ − Var(p_A)/(1 − μ)；μ = .5 且题目 p_A 各为 0 或 1 时 R_pop = 0。这不是本次有限账本 R 的代数恒等式。总体组成差还取决于 p_B − p_A 与筛选概率的协方差，方向不定。本次账本 R = 0、A 在 24/30 题上四槽全对或全错，只是描述，不据此推断 p_A。
5. 判分层用该 revision 存储的 correct；没有重判，没有另写宽松判分；已保存的拒答、截断按原 correct 计（本框内没有截断或空答案）。原 parser 版本 UNKNOWN。“可解释的最终答案判分”按“correct 为已存布尔值且 gold 非空”执行，没有逐条审读解析。
6. 若需概率机制解释，可向 MathArena 作者请求原始调用时间、resolved endpoint、完整提示、尝试/重试与替换链、判分版本及 usage 归属；本次不联系、不补调用。缺这些材料限制解释范围，不否定有限账本研究。
7. 合同里“共同题文/gold与完整提示”有两种读法（提示须相同，或只须完整）；本次 8 槽提示在 30 题上逐字相同，两种读法结果一样。
8. 预先确定的操作定义（在使用 correct 取值之前写进代码，frame/frame.json 记录，只读）：
   - 配置对应：原始 model_config 去掉固定前缀 configs/models/ 与后缀 .yaml 后等于官网标识（或以 /标识 结尾），或其行的 model_name 恰等于官网显示名；每侧恰好收集到一个原始值、两侧不同、各只带一个 model_name 才算明确，否则 NA
   - 题目按 problem_idx 识别；候选题 = 冻结副本全部行中出现的不同 problem_idx，须为 30
   - 每侧 idx 0..3 各恰一条（完全相同的重复行折叠为一条）；同键内容不同或出现 0..3 以外的 idx 即违约
   - 共同题文/gold：每题 8 条保留记录的 problem 与 gold_answer 各只有一个取值
   - 完整提示：每条 user_message 非空且 all_messages 为含 user 轮的 JSON 列表；A/B 提示是否逐字相同只作调用条件属性报告，不据此删题
   - 判分：correct 为已存布尔值（非空），gold_answer 非空
   - 响应状态：answer 非空即保留（token 记 0 也保留，usage 按原记账层级读）；answer 空且 output_tokens>0 为已保存截断，按原 correct 计；answer 空且 output_tokens 空/0 为未知响应状态，不冒充答错，构成违约
   - 任一题违约即整轮 NA：不删题、不换配置
   - 主量固定 p0 = idx0 筛选、idx1–3 复评；四槽循环（筛选槽 = idx j）只作敏感性
   第一阶段为核对“correct 无缺失、为布尔值”解码过 correct 列，但只保留是否为空、是否布尔两个标志（另有仅在内存中用于区分重复行的行摘要），取值未输出、未用于任何计算。
